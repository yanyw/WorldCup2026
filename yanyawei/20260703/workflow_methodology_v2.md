# World Cup Polymarket 工作流 v2

## 目标

在未来四天的比赛中，用同一标准生成可复算、可审计、费用后仍有正 Edge 的分散组合。工作流只生成建议和限价，不自动下单。

## 相对 v1 的主要改进

1. 不再按每个盘口单独估概率。每场只生成一组进球率，再统一推导胜平负、让球、大小球和 BTTS。
2. 不再把三场小组赛均值直接外推。使用带 L2 收缩的攻防强度模型，并对异常红牌比赛降权。
3. 不再只依赖内部模型。引入市场反推进球率、Opta 25,000 次模拟和独立赛前分析进行校准。
4. 区分“模型概率”和“交易概率”。交易概率取多源证据的保守值，不机械使用最高概率。
5. Kelly 只计算一次，再乘固定比例和置信度折扣；禁止重复相乘。
6. 组合最多每场一笔，优先跨比赛分散；没有达到限价时不为增加交易数量而追价。
7. 数据、模型输出、人工校准和最终决策分别保存，便于复盘每一层误差。

## 完整流程

### 双代理两轮审计协议

每期结论按以下顺序运行两轮，不允许审核代理直接改写最终组合：

1. 分析代理完成数据、模型、候选和初版组合。
2. 审核代理只负责寻找反证：盘口方向、结算规则、去水、费用、概率一致性、同源数据、伤停、仓位相关性和执行可行性。
3. 分析代理逐条回复 `接受 / 部分接受 / 拒绝`，每项必须给出计算或来源；不得为了与审核意见一致而改结论。
4. 分析代理形成第一轮返修版。
5. 审核代理对返修版进行第二轮审核，重点检查修复是否引入新矛盾。
6. 分析代理再次独立裁决，形成最终版并保留争议项记录。

审核意见是反证输入，不是投票。增加下注数量也不能绕过最低 Edge、订单簿可成交性和每场一笔的约束。

### 最终组合的强制披露模板

最终决策文档不能只给方向、价格和金额。对组合中的每一笔下注，必须在“最终组合”部分逐项披露：

1. 合约的准确结算含义，明确90分钟、让球方向、总进球或BTTS条件。
2. 两队进入模型的FIFA比赛场次、进失球、累计xG和xGA；异常比赛如何降权。
3. `lambda_xG`和`lambda_goals`，并说明它们分别来自FIFA xG与历史实际进球。
4. `lambda_data = 85% xG + 15%实际进球`及由其生成的`P_data`。这一层才可称为纯内部模型。
5. `lambda_market`、可用时的`lambda_Opta`、融合权重、`lambda_final`和`P_final`。
6. 从`P_data/P_final`调整到`P_trade`的每一项外部证据、反证和保守折扣，禁止只给人工结果不解释。
7. 所买token的CLOB最佳bid/ask、maker/taker上限、逐市场费率、当前和上限处的费用后Edge。
8. 费用后Kelly成本、Full Kelly、fractional Kelly、置信折扣和最终USDC仓位。
9. 首发、伤停、盘口线或价格变化对应的撤单条件。

报告必须始终使用`纯内部概率`、`融合模型概率`和`交易概率`三个不同名称。不得把已经融合Polymarket或Opta的数据称为内部模型，也不得用maker挂单数量冒充已成交仓位。

### 1. 固定分析窗口与市场规则

- 每次覆盖未来三至四天的全部比赛，不按距离开赛时间降低研究标准。
- 所有 Game Lines 均按常规时间 90 分钟及补时结算，不含加时和点球。
- 记录买价、盘口线、成交方式、抓取时间和来源 URL。
- 买价不是无水概率；三项胜平负和二元盘口都可能因点差而超过 100%。
- 从Gamma API分别读取主事件和`more-markets`事件及token ID；模型使用盘口中间价，执行价直接查询所买YES/NO token的CLOB订单簿，禁止用页面中间价或`1-YES`推导价假设可以成交。

### 2. 获取官方比赛数据

从 FIFA Match Report Hub 自动发现并解析 PDF，提取：

- 进球与失球
- xG 与 xGA
- 射门与被射门
- 射正与被射正
- 比赛阶段和对手

淘汰赛报告权重为 1.25，小组赛为 1.0。加拿大 6:0 卡塔尔因对方两张红牌降至 0.35，防止单场异常把加拿大攻击强度永久抬高。

### 3. 构建内部进球率

使用中立场攻防模型：

`log(lambda_i_vs_j) = mu + attack_i + defensive_vulnerability_j`

目标函数采用 Poisson 准似然，并对攻防参数做 L2 收缩。分别拟合：

- xG 模型，权重 85%
- 实际进球模型，权重 15%

两者按对数空间加权，既避免完全忽视持续终结能力，也防止四场比赛的进球运气主导预测。

### 4. 生成外部锚点

1. 将 Polymarket 去水后的胜平负与总进球盘口拟合成市场隐含进球率。
2. 有 Opta 单场模拟时，将其胜平负拟合成 Opta 隐含进球率。
3. 没有 Opta 时，提高内部数据权重，同时扩大不确定性区间。

有 Opta 时的基础权重：内部数据 35%、Opta 40%、市场 25%。
无 Opta 时：内部数据 55%、市场 45%。

这些权重用于形成统一比分分布，不等于最终下注概率。

### 5. 统一推导盘口

比分矩阵为：

`P(i:j) = Poisson(i; lambda_home) * Poisson(j; lambda_away)`

由同一矩阵计算：

- 胜、平、负
- 一方净胜两球及以上
- 两队合计进球大于或小于盘口线
- 两队是否都进球

验证器强制检查胜平负、让球两侧、大小球两侧和 BTTS 两侧分别相加为 100%。

### 6. 不确定性与外部反证

- 对最终进球率进行对数正态扰动，生成 4,000 次场景模拟和 10%-90% 区间。
- 有 Opta 的比赛使用较小波动，无 Opta 的比赛使用更宽波动。
- 逐个候选搜索阵容、伤停、战术和其他模型。
- 外部证据明确反对时，即使内部 Edge 很大也跳过。例如加拿大胜、佛得角 +1.5 和 Ghana +1.5 均因模型间冲突没有进入当前组合。

### 7. 形成交易概率

交易概率不是简单平均，而是内部模型、Opta、外部赔率和战术证据共同支持的保守值：

- 多源同向：接近模型中枢，但不使用最高值。
- 只有内部模型支持：降低至外部合理区间或跳过。
- 来源冲突：提高买入门槛，必要时只挂低于现价的条件单。

### 8. 费用和限价

Maker 不收费。Taker 费用：

`fee = shares * 0.03 * price * (1-price)`

其中 `shares` 是份额，不是投入的 USDC。若投入金额为 `stake = shares * price`，等价公式为：

`fee = stake * 0.03 * (1-price)`

因此体育盘口的 `0.03` 不是直接收取投入金额的 3%；在 40c-60c 附近，有效费用约为投入金额的 1.2%-1.8%，或每份额约 0.72c-0.75c。计算默认不预先扣除用户可能获得的 taker tier rebate。

因此：

`maker_edge = trade_probability - price`
`taker_edge = trade_probability - price - 0.03 * price * (1-price)`

所有入选仓位在 maker 最大买价处至少保留 4 个百分点 Edge。若允许 taker，可设置更低的独立 taker 上限；该上限处的费用后 Edge 也必须不少于 4 个百分点。

### 9. 一次 Kelly 和组合约束

`full_kelly = (p - c) / (1 - c)`

执行顺序固定为：

`Full Kelly -> 0.15 fractional Kelly -> 置信度折扣 -> 单笔上限`

Taker的Full Kelly必须以`price + fee_per_share`作为实际合约成本；maker费用为零。组合状态分为`TAKER_ACTIONABLE`和`MAKER_ORDER`，后者只表示建议挂单，不表示已经成交。

组合约束：

- 单场最多一笔
- 单笔最多 bankroll 的 1.2%
- 全部条件单成交后最多 5%
- 同场相关盘口不重复买入
- 当前价格不合格时保留低价 maker 单，不追价

### 10. 临场和赛后

每场开赛前 60 分钟：

1. 刷新盘口和订单簿。
2. 确认首发、门将、中卫和核心攻击手。
3. 用实际买价重算费用后 Edge。
4. 任一撤单条件触发时取消，不用其他盘口替代。

验证器要求实时盘口、模型和决策文件使用同一时间戳；快照超过 30 分钟会拒绝通过。临场必须按“刷新 -> 建模 -> 更新决策 -> 校验”的顺序执行。

赛后记录：成交价、收盘价、结果、收益、Brier score、log-loss 和是否击败 closing line。模型优劣不能只按单场盈亏判断。

- `scripts/fetch_fifa_reports.py`：抓取并解析 FIFA 报告
- `scripts/refresh_polymarket_0702.py`：刷新主盘口、更多盘口和订单簿买卖价，并自动更新组合的当前价与可执行状态
- `scripts/build_model_0702.py`：拟合模型并生成概率
- `scripts/validate_portfolio_0702.py`：检查概率一致性、费用 Edge 和组合上限
